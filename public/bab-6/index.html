Bab 6: Pengelolaan Informasi1

A. Pengenalan Basis Data

1. Data vs Informasi

Data

Kumpulan fakta mentah yang belum diolah dan tidak memiliki arti bagi penerimanya. Contoh: Angka 37, 38, 39.

Informasi

Data yang telah diolah sehingga memiliki konteks dan manfaat. Contoh: "Suhu tubuh 39°C menandakan gejala demam."

"Ibarat masakan, data adalah bahan mentah (wortel, kentang), sedangkan informasi adalah sayur sop yang sudah matang dan siap dinikmati."

Bab 6: Pengelolaan Informasi2

2. Klasifikasi Data

Data dapat dikelompokkan berdasarkan beberapa kategori penting:

Berdasarkan Bentuknya

  • Numerik (Angka/Nilai)
  • Tekstual (Kata/Kalimat)
  • Visual (Gambar/Video)
  • Audio (Suara)

Berdasarkan Sifatnya

  • Kualitatif: Deskriptif, tidak berupa angka (Contoh: Warna, Nama).
  • Kuantitatif: Berupa angka hasil pengukuran (Contoh: Tinggi badan, Harga).

3. Apa itu Basis Data?

Basis Data (Database) adalah kumpulan data yang disimpan secara sistematis di dalam komputer yang dapat diolah atau dimanipulasi menggunakan perangkat lunak (DBMS) untuk menghasilkan informasi.

4. Peran dalam Lingkungan Basis Data

a. Administrator Basis Data (DBA)

Bertanggung jawab penuh atas keamanan, performa, dan pemeliharaan sistem. Mereka mengatur siapa yang boleh masuk dan menjaga agar data tidak hilang.

b. Desainer Basis Data

Arsitek data. Mereka merancang bagaimana informasi harus disusun, tabel apa saja yang dibutuhkan, dan bagaimana antar tabel berhubungan.

Bab 6: Pengelolaan Informasi6

c. Pengembang Aplikasi

Membangun program (web/mobile) yang berinteraksi dengan basis data. Mereka menulis kode untuk mengambil data dan menampilkannya kepada pengguna.

d. Pengguna Akhir (End-Users)

Orang-orang yang menggunakan aplikasi setiap hari (seperti kita saat belanja online). Mereka memasukkan atau mencari data melalui antarmuka yang ramah pengguna.

Tugas Utama: Berkolaborasi untuk Sistem yang Handal

B. Jenis-Jenis Basis Data

1. Basis Data Relasi

Data disimpan dalam bentuk tabel yang saling terhubung. Contoh: MySQL, PostgreSQL. Paling umum digunakan karena strukturnya yang jelas.

2. Basis Data NoSQL

Tidak menggunakan struktur tabel yang kaku. Sangat fleksibel untuk data yang berubah-ubah (seperti post media sosial). Contoh: MongoDB.

Bab 6: Pengelolaan Informasi9

3. Basis Data Berbasis Cloud

Disimpan di server internet (Cloud). Kamu bisa mengakses data dari mana saja selama ada koneksi. Contoh: Google Firebase, AWS RDS.

4. Basis Data Terdistribusi

Data tidak berada di satu tempat saja, tapi tersebar di berbagai lokasi fisik (misal: server Jakarta, server Palembang, server Papua) namun tetap bekerja sebagai satu kesatuan.

Bab 6: Pengelolaan Informasi10

Teknologi Pendukung

📋

Replikasi

Menyalin data dari satu server ke server lain agar jika satu rusak, data masih ada di tempat lain.

🪞

Mirroring

Membuat salinan data secara "real-time" (seketika itu juga) sebagai cadangan utama.

Bab 6: Pengelolaan Informasi11
🏭

Data Warehouse

Gudang penyimpanan data yang sangat besar untuk keperluan analisis bisnis jangka panjang.

📈

Big Data

Teknologi untuk menangani volume data yang raksasa, cepat, dan beragam (misal: data transaksi seluruh dunia).

"Memilih jenis basis data yang tepat seperti memilih baju: harus sesuai dengan kebutuhan dan ukuran proyekmu."

Bab 6: Pengelolaan Informasi12

C. Basis Data Relasi

Entitas

Entitas adalah sesuatu yang memiliki keberadaan unik dan berbeda di dunia nyata yang ingin kita simpan datanya.

👤

Contoh Entitas:

  • Benda Konkret: Buku, Peserta Didik, Guru.
  • Peran/Fungsi: Karyawan, Pelanggan, User.
  • Kejadian: Peminjaman, Transaksi, Nilai.
Bab 6: Pengelolaan Informasi13

Atribut

Atribut adalah detail atau ciri khas yang menjelaskan sebuah entitas. Dalam tabel, atribut direpresentasikan sebagai kolom.

1. Atribut Kunci (Key)

Unik untuk membedakan satu baris dengan baris lain. Contoh: NIS pada data siswa.

2. Atribut Sederhana (Simple)

Nilainya tidak bisa dipecah lagi. Contoh: Jenis Kelamin, Tahun Terbit.

Bab 6: Pengelolaan Informasi14

3. Atribut Komposit

Atribut yang bisa dipecah menjadi bagian-bagian kecil. Contoh: Alamat (Jalan, RT/RW, Kota, Kode Pos).

4. Atribut Multivalue

Satu orang bisa punya lebih dari satu nilai. Contoh: Nomor Telepon (bisa punya 2 nomor), Hobi.

Catatan: Sebaiknya atribut komposit dipisah menjadi kolom sendiri agar data mudah dicari!

Bab 6: Pengelolaan Informasi15

5. Atribut Turunan (Derived)

Atribut yang nilainya didapat dari hitungan atribut lain. Contoh: Usia (didapat dari: Tahun Sekarang - Tahun Lahir).

Tipe Data

Setiap atribut harus memiliki tipe data yang jelas agar komputer tahu cara menyimpannya dengan benar. Salah memilih tipe data bisa membuat database jadi lambat atau error!

Bab 6: Pengelolaan Informasi16

Kategori Tipe Data

A. Numerik (Angka)

Untuk data yang bisa dihitung (Matematika).

INT, FLOAT, DECIMAL

Contoh: Stok barang (50), Nilai (85.5).

B. Teks (Karakter)

Untuk huruf, kalimat, atau angka yang tidak dihitung.

CHAR, VARCHAR, TEXT

Contoh: Nama (Dela), Kode Pos (30128).

Bab 6: Pengelolaan Informasi17

C. Tanggal & Waktu

Untuk menyimpan momen waktu secara akurat.

DATE, TIME, DATETIME, YEAR

Contoh: Tgl Lahir (2007-10-05).

D. Boolean (Logika)

Hanya dua kemungkinan: Benar atau Salah.

BOOLEAN (T/F atau 1/0)

Contoh: Sudah Lulus? (Ya/Tidak).

Bab 6: Pengelolaan Informasi19

Rambu-Rambu Penamaan Tabel

Agar sistem tidak error, ikuti aturan ini saat memberi nama tabel:

  • ✓ Deskriptif: Harus mencerminkan isinya (Contoh: data_peserta_didik).
  • ✗ Tanpa Karakter Khusus: Jangan pakai spasi atau tanda baca (!@#).
  • ✓ Konsisten: Gunakan format snake_case (huruf kecil semua dipisah garis bawah).
  • ✗ Hindari Keyword: Jangan pakai kata select, table, or user.

Kardinalitas menggambarkan jumlah maksimal hubungan antara satu data di sebuah tabel dengan data di tabel lain.

1. One to One (1:1)

Satu baris di tabel A hanya boleh berpasangan dengan satu baris di tabel B.

Bab 6: Pengelolaan Informasi23

Primary Key (PK)

🔑

Kunci Utama. Atribut yang nilai tiap barisnya HARUS UNIK dan tidak boleh kosong.

Syarat Primary Key:

  • ● Tidak boleh ada dua nilai yang sama (Unik).
  • ● Tidak boleh bernilai kosong (Not Null).
  • ● Bersifat tetap dan tidak berubah.
Bab 6: Pengelolaan Informasi24

Foreign Key (FK)

Kunci Tamu. Adalah kolom di sebuah tabel yang merujuk ke Primary Key di tabel lain. Berfungsi sebagai jembatan yang merelasikan dua tabel.

Visualisasi Relasi:

Tabel Siswa: (NIS-PK, Nama)
⬇️
Tabel Pinjam: (ID_Pinjam, NIS-FK, Buku)
Bab 6: Pengelolaan Informasi25

Jenis Tabel dalam Relasi

1. Tabel Referensi (Master)

Menyimpan data utama yang jarang berubah. Contoh: Tabel Siswa, Tabel Barang, Tabel Guru.

2. Tabel Transaksi

Menyimpan catatan aktivitas yang terjadi berkali-kali. Contoh: Tabel Penjualan, Tabel Peminjaman, Tabel Absensi.

💡

"Foreign Key membantu sistem mengenali 'Siapa' (Master) melakukan 'Apa' (Transaksi) tanpa harus mengulang data yang sama."

Server Lokal

Structured Query Language (SQL)

Bab 6: Pengelolaan Informasi31

Operasi SQL: Membuat Database

CREATE DATABASE db_sekolah;

Langkah awal untuk menyiapkan "wadah" besar data sekolah.

Membuat Tabel

CREATE TABLE siswa (
  nis INT PRIMARY KEY,
  nama VARCHAR(100),
  kelas VARCHAR(10)
);

Kita membuat kolom NIS sebagai Primary Key agar tidak ada data siswa ganda.

Bab 6: Pengelolaan Informasi32

Operasi SQL: Menambah Data

INSERT INTO siswa (nis, nama, kelas)
VALUES (22201, 'Budi Santoso', 'X-1');

Menampilkan Data

SELECT * FROM siswa;

Gunakan tanda bintang (*) untuk menampilkan SEMUA kolom.

SELECT nama FROM siswa WHERE kelas = 'X-1';

Gunakan WHERE untuk memfilter data spesifik (misal: hanya kelas X-1).

Bab 6: Pengelolaan Informasi33

Operasi SQL: Mengubah & Menghapus

UPDATE siswa
SET kelas = 'X-2'
WHERE nis = 22201;

Peringatan: Selalu gunakan WHERE saat UPDATE agar tidak semua data berubah!

DELETE FROM siswa WHERE nis = 22201;

Hati-hati dengan perintah DELETE!

E. Pengolahan Data Dasar

Sebelum beralih ke basis data yang rumit, kita bisa memulai dengan Spreadsheet (seperti Excel atau Google Sheets).

Spreadsheet

  • Data skala kecil
  • Mudah diedit langsung
  • Cocok untuk analisis cepat

Basis Data

  • Data skala besar
  • Keamanan ketat
  • Terhubung ke aplikasi
Bab 6: Pengelolaan Informasi35

Sumber Pengumpulan Data

A. Data Primer

Data yang kamu kumpulkan sendiri secara langsung dari sumbernya. Contoh: Melakukan wawancara, mengisi angket kuesioner, atau melakukan eksperimen sendiri.

B. Data Sekunder

Data yang didapat dari pihak lain yang sudah mengumpulkannya. Contoh: Mencari data jumlah penduduk dari BPS atau membaca dataset dari internet.

Bab 6: Pengelolaan Informasi36

Rangkuman Materi

● Basis data adalah kunci pengelolaan informasi digital yang sistematis.

● Entitas dan Atribut membentuk struktur dasar tabel relasi.

● Primary Key (PK) memastikan setiap data bersifat unik.

● SQL (Structured Query Language) adalah bahasa standar dunia untuk bicara dengan basis data.

● Spreadsheet adalah alat awal yang hebat untuk belajar pengolahan data sebelum masuk ke DBMS.
